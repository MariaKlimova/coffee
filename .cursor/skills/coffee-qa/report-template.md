# Шаблон QA-комментария

Заполнить фактами, убрать подсказки и необязательные пустые секции. Каждый
обязательный AC должен присутствовать в матрице; строки ниже — пример структуры.
Использовать формат, поддерживаемый текущим connector, не предполагать HTML/media.

```markdown
## QA — COFFEE-N — PASS / FAIL / BLOCKED

- Run ID / дата / timezone: ...
- Требования: тикет, важные комментарии, время чтения.
- Checkout: branch / полный HEAD / base SHA.
- Scope: committed + staged/unstaged/untracked задачи; чужие изменения исключены.
- Snapshot: имя manifest, SHA-256 файлов scope до/после; совпал / изменился.
- Окружение: local synthetic / local real API / preview; revision API/frontend,
  PostgreSQL/storage real или mock; YooKassa demo/mock/не затронута.
- Браузер: имя/версия, viewport, desktop/touch; либо причина BLOCKED/skip.
- Соответствие runtime исходникам: подтверждено ... / неизвестно ...

### Покрытие AC

| AC / источник | ID | Сценарий / ожидаемый результат | Слой | Итог | Evidence / ограничение |
|---------------|----|-------------------------------|------|------|------------------------|
| ... | T1 | ... | unit/API/browser | PASS/FAIL/BLOCKED | ... |

### Команды

| Команда / revision | Результат / exit | Краткий итог | Источник |
|--------------------|------------------|--------------|----------|
| ... | ... | ... | запуск QA / проверенный лог той же ревизии |

### Browser — T1

Предусловия: безопасный URL, synthetic данные/роль, viewport, исходное состояние.
1. Действие → ожидание → фактический результат.
2. Действие → ожидание → фактический результат.

Evidence: имена файлов и подтверждённые attachment IDs/ссылки либо ограничение upload.
Если browser не запускался: причина и какие AC остались BLOCKED или нерелевантны.

### Дефекты и ограничения

- Severity blocker/major/minor, шаги воспроизведения, expected/actual, кому вернуть.
- Непроверенные AC, моки, неизвестная revision/deployed интеграция, доступность evidence.

### Evidence и cleanup

- Manifest / файлы: имена и назначение; без локальных ссылок и секретов.
- Вложения в Jira: подтверждённые IDs/URL либо «скриншоты не загружены ...».
- Ресурсы: исходные пользовательские ресурсы сохранены; собственные tab/CDP/browser/
  dev-server освобождены, synthetic данные очищены или изолированы для воспроизведения.

### Вывод

Почему PASS/FAIL/BLOCKED следует из покрытия; необходимые действия.
Повторная приёмка: предыдущий отчёт, новая revision и перепроверенные сценарии.

_QA Tester · статус и assignee не менялись · bug-тикеты не создавались_
```
