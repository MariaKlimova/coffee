# QA-комментарий и evidence в Jira

1. Обнаружить Jira/Atlassian connector и его фактические схемы. Работать с сайтом
   `https://klimovamaria5227.atlassian.net` и выбранным `COFFEE-N`.
   Прочитать тикет и комментарии с пагинацией.
2. Подготовить [отчёт](report-template.md) с уникальным run ID, покрытием AC,
   revision/runtime, результатами и ограничениями. Вызов QA/workflow уже разрешает
   этот комментарий; повторно согласовывать его не нужно. Удалить чувствительные
   данные и не вставлять полный необработанный лог.
3. Использовать документированную операцию добавления комментария, например
   доступный `addcommenttojiraissue` с поддерживаемым Markdown/ADF. Не угадывать
   имена tools, ID, HTML/inline media и параметры из другого connector.
4. Подтвердить сохранение по comment ID и телу в ответе либо перечитать комментарии.
   Сохранить подтверждение в manifest. При наличии ID дать ссылку вида
   `https://klimovamaria5227.atlassian.net/browse/COFFEE-N?focusedCommentId=ID`.

## Повтор без дублей

После timeout/неопределённого ответа сначала перечитать комментарии с пагинацией
и найти run ID. Уже опубликованный отчёт повторно не отправлять. Если чтение
недоступно или исход всё ещё неясен, остановить retry, вернуть готовый локальный
текст и сообщить неопределённость. Новая приёмка исправленной ревизии — новый run
с содержательным отчётом и ссылкой на предыдущий, а не сетевой retry.

## Вложения

- До upload проверить файл и кадр; только evidence из разрешённой тестовой среды.
  Исключить реальные контакты/адреса, заказы покупателей, JWT/cookies/секреты,
  payment/access URLs и сырые payload. Переснять на synthetic данных вместо
  публикации чувствительного кадра.
- Использовать только реально доступный документированный upload/attachment tool
  или отдельно настроенный разрешённый Jira API. Не копировать credentials или
  приватные helpers соседнего проекта. Отсутствие upload не требует настройки
  нового доступа ради обязательного текстового отчёта.
- После upload сохранить подтверждённые IDs/URL и сослаться способом connector.
  Если исход неясен, проверить вложения перед retry; не создавать дубликаты.
- Без upload **всё равно отправить текстовый комментарий**, указав:
  «Скриншоты не загружены: инструмент загрузки недоступен; evidence сохранено локально
  и недоступно из Jira». Дать имена файлов/manifest, не фиктивные attachments.
- Локальные абсолютные пути/`file://` не являются ссылками для читателя Jira;
  их передать координатору отдельно. Вердикт определяется проверенными AC,
  доступность evidence и публикации указать отдельно. Если необходимое для вывода
  evidence потеряно, повторить проверку либо отметить BLOCKED.

Если запись комментария недоступна, сохранить отчёт локально и явно сообщить
«QA-комментарий не опубликован». Не менять статус/assignee/описание задачи вместо
комментария и не объявлять QA-этап полностью завершённым без публикации.
