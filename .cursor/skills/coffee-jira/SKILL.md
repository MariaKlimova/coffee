# Jira Coffee

Проект `COFFEE`: https://klimovamaria5227.atlassian.net/jira/software/projects/COFFEE.
Репозиторий: https://github.com/MariaKlimova/coffee.

- Использовать доступный Jira/Atlassian connector и его документированные схемы.
  Определить site/cloud ID по этому сайту; не угадывать IDs типов, переходов или полей.
- Перед реализацией/QA читать актуальное описание, AC, важные комментарии
  с пагинацией и зависимости. Уточнения задачи брать из тикета, а не из памяти.
  Недоступный обязательный контекст обозначать явно, не подменять предположениями.
- Перед созданием искать существующие задачи. COFFEE-40 уже планирует SPA-админку
  каталога; новые работы не должны её дублировать. Формулировать проблему,
  ожидаемое поведение, проверяемые AC, зависимости и способ проверки.
- Вносить только изменения, разрешённые запросом. QA-приёмка по
  [coffee-qa](../coffee-qa/SKILL.md) включает комментарий результата; статус,
  assignee, описание задачи и новые bug-тикеты этим не разрешены.
- Ветка задачи — `feat/COFFEE-N-short-name` / `fix/COFFEE-N-short-name`;
  в PR указать ссылку и результаты проверок. Не объявлять Done по факту написанного
  кода: учитывать критерии, review, QA и требуемый merge/deploy.
- Подтвердить внешнюю запись по ответу/чтению результата. Для QA использовать run ID;
  после timeout сначала найти его в комментариях, затем решать о retry без дублей.
  Не печатать секреты, реальные контакты покупателей и необработанные payload.
