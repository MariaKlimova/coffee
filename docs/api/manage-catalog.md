# Управление каталогом

Все `/api/manage/` endpoints требуют JWT активного staff. Анонимный запрос
получает 401, покупатель — 403. Полный контракт находится в `openapi.yaml`.

- `GET/POST /api/manage/products/`: список всех товаров и создание рабочего
  товара. Фильтры `category`, `search`, `is_published`, `origin`, `in_stock`,
  `price_min`, `price_max`, `ordering`; пагинация `page/page_size`.
- `GET/PATCH/DELETE /api/manage/products/{uuid}/`: просмотр, изменение и снятие
  публикации. DELETE сохраняет сам товар, галерею, остатки и связи с заказами.
- `GET /api/manage/catalog/`: сохранённое состояние demo и количества demo,
  рабочих и опубликованных рабочих товаров для подтверждения перехода в SPA.
- `POST /api/manage/catalog/disable-demo/`: необратимое в интерфейсе отключение
  demo. Повторный запрос возвращает прежние дату и состояние перехода.

При создании обязательны `name`, `category` (slug), `short_description`, `price`
и `stock_quantity`. Slug генерируется сервером и не меняется при переименовании.
`attributes` целиком заменяет объект характеристик и проверяется по итоговой
категории; смена категории не очищает характеристики молча.

`stock_quantity` — физический остаток, JSON integer от 0 до 2147483647.
`reserved_quantity` и `available_quantity` возвращаются только для чтения;
наличие вычисляется. Изменения количества идут через `adjust_stock` под блокировкой
строки товара и записывают actor, дату, старое/новое значение и причину.
`stock_change_reason` необязателен; стандартная причина — `Catalog stock adjustment`.
Уменьшение ниже текущего резерва возвращает `400 errors.stock_quantity` и откатывает
все поля этого PATCH. Покупатель не может записывать эти поля.

`origin=demo|owner` и `demo_source` назначает сервер. Миграция помечает только
18 UUID, действительно созданных импортом COFFEE-64
`catalog-data-20261101T123258089703Z`; совпадение названия/slug не является
доказательством происхождения. `seed_catalog` помечает только вновь созданные
записи и оставляет существующие данные, файлы и остатки нетронутыми.

Редактирование demo требует явного `save_as_owner=true` в PATCH. Без него API
возвращает ошибку этого поля, чтобы изменения не потерялись при отключении demo.
Этот же PATCH может содержать только `save_as_owner=true`: UUID, slug, исходный
`demo_source`, галерея и связи сохранятся, а origin станет `owner`.

Файлы-заглушки помечены `images[].is_mock`. `has_uploaded_images` считает только
реальные загруженные фотографии. После сохранения demo как рабочего его mock
файлы остаются видны в manage, но публичный ответ их не отдаёт. Frontend должен
использовать `origin` при выборе временной static mock-картинки; UUID сам по себе
не даёт права показывать mock у рабочего товара.

Отключение demo сохраняет все строки. Публичные list/detail/related и избранное
их скрывают; добавление в корзину и новый checkout их отклоняют. Уже созданные
заказы и резервы продолжают штатный жизненный цикл. Неопубликованность отличается
от скрытого demo через `hidden_reason`; при обеих причинах приоритет у
`unpublished`. Обычный seed, reload и повторное применение миграций не включают
demo обратно. Рабочие товары можно создавать до и после перехода.

Миграции и переключение production выполняются отдельно от сборки. Не откатывать
схему с удалением полей происхождения/состояния после перехода: это потеряет
сохранённое решение владельца. Для отката приложения сохранять совместимую схему.
